## 二、每步流程约定（评审协议 · 快速档）

1. AI 完成一步 → 立即跑全部测试（`npm test`）+ 该页浏览器冒烟 → 全绿后停下汇报。
2. 汇报固定四块：**改了哪些文件 / 测试结果 / 浏览器怎么验证 / 揪出的契约问题**。
3. 你按「第四章 审查方法」评审，通过后回复通过 → AI 打一个 commit（如 `step1: 规则配置切新契约`）→ 开始下一步。
4. 不通过就打回：贴报错截图/失败测试名/页面异常，AI 修复后重新走 1-3。
5. 每步一 commit，`git log` 即迁移史，出问题可精准回滚某一步。

## 三、测试体系（四层，各自保证什么）

| 层 | 跑在哪 | 保证什么 |
|----|--------|---------|
| L1 单元 | vitest `tests/unit/` | 纯函数行为（解包、错误提取、状态映射、校验） |
| L2 契约 | vitest `tests/contract/` | 请求形状与文档一字不差；文档示例响应被正确解包。**后端实现与文档不符时，联调一接上就红** |
| L3 组件 | vitest | 页面挂载、关键交互（审核 payload、驳回必填、高危确认） |
| L4 冒烟 | Playwright `tests/e2e/` | 真浏览器跑该页主链路，截图存 `tests/e2e/snapshots/` |

## 四、如何审查（实操教学）

### 4.1 跑测试（1 分钟）

```bash
cd E:/action/EasyPoints/apps/admin-web
npm test
```

- 看最后一行 `Tests  N passed`：数量与汇报一致且全绿即通过。
- 有 failed 时：把失败的用例名和报错贴给 AI 即可，不用自己修。
- 注意：必须在 `apps/admin-web` 目录下跑（在仓库根跑会扫错目录）。

### 4.2 读汇报（2 分钟，重点看三处）

- **改动文件清单**：是否只有本步该动的文件？出现无关文件 = 范围蔓延，打回问原因。
- **契约问题**：每条想一想「后端文档是不是真这么写的」，拿不准的自己去文档里搜一下关键词。
- **浏览器验证点**：照着下一节操作。

### 4.3 浏览器验证（2 分钟，核心技能：F12 核对契约）

打开 http://localhost:5173，登录后进入本步改的页面，然后：

1. **页面功能**：该页主流程走一遍（列表加载、筛选、弹窗、提交），与我汇报的预期一致。
2. **F12 → Network 面板**：刷新页面，点击左侧列表里的一条 `/admin/...` 请求：
   - **Headers 页**看 Request URL 和 Query String 参数——对照 API 文档该接口的参数表，名字、传参应该一字不差；
   - **Response 页**看返回 JSON——应该是 `{code:1, msg, data}` 包装，data 里字段名与文档一致。
   - 这一步是你独立验证「前后端契约对齐」的手段，不用等 AI 汇报。
3. **Console 面板**：红色报错贴给 AI（黄色警告一般可忽略）。

> 后端暂无数据时页面可能空列表——这正常；此时主要核对 Network 里请求形状对不对、报错文案是否可读，数据等后端就绪后联调。
